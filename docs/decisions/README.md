# decisions/

Architecture Decision Records (ADRs) for this project.

For studio-wide decisions (stack, conventions, CI), use `studio-docs/decisions/`.

---

## When to create an ADR

Create an ADR when a decision:
- Affects the architecture, data model, or system design of this project
- Has viable alternatives that were considered and rejected
- Would be difficult to reverse without context on why it was made

**Do not create ADRs for:** obvious choices, trivial decisions, or style preferences.

---

## How to create

1. Copy the template below to `ADR-XXX-short-title.md`
2. Fill it in at the time of the decision — not retroactively
3. Number sequentially: `ADR-001`, `ADR-002`, etc.

---

## Template

```markdown
# ADR-XXX — [Short title]

**Date:** YYYY-MM-DD
**Status:** Accepted | Superseded by ADR-YYY
**Decided by:** CTO

## Context

Why this decision was needed. What problem or trade-off it addresses.

## Decision

What was decided.

## Alternatives considered

| Alternative | Reason for rejection |
|---|---|
| ... | ... |

## Consequences

What changes. Known risks. What becomes easier and what becomes harder.
```
